# R3 findings: tools/check-superfleet.py

Question: which functions do behaviour that the docstring does not describe?
The module docstring (lines 2-20) is the only docstring in the file. Its "The plan fails if" list (lines 12-14) and "The review fails if" paragraph (lines 16-17) are the description checked against.

Count: 11

## Findings

- `check_plan`, lines 39-41: fails when a scenario id appears more than once. The docstring's fail list (lines 12-14) does not mention duplicate ids.
- `check_plan`, lines 44-48: fails when a scenario id is not of the form `S01`, and when `title`, `goal`, `look_first` or `review` is empty. None of these is in the docstring's fail list.
- `check_plan`, lines 63-64: fails when a lane lacks `covers`, as well as `done_when`. The docstring says only "a lane has no done-test".
- `check_plan`, lines 65-66: fails when a write area does not end in `/` or contains `..`, as well as when it lies outside `docs/ai-cto/fleet/`. The docstring names only the location rule.
- `check_plan`, line 51: the Matrix-method test is a substring search for `"<method>"` anywhere in `tools/matrix.py`. A name that appears only in a comment or a string passes. The docstring says the look-first step must name a method "that does not exist", which describes an existence check, not a text search.
- `check_plan`, lines 56-57: fails when a look-first step names neither a Matrix method nor a `tools/check-*.py` file. The docstring covers only a named method or check that does not exist, not a look-first step that names neither.
- `review`, line 79: compares the branch with `origin/leader...{branch}` (the remote tracking ref, three-dot form). The docstring says the comparison is with the branch `leader`.
- `review`, lines 77-78: returns a failure when the lane is not in the plan. The docstring does not describe this path.
- `review`, lines 85-86: fails when the branch changed nothing. The docstring describes only the outside-write-area failure.
- `main`, lines 100-102: a `--review` call with other than three arguments prints a usage failure and exits 1. The docstring lists the `--review` usage but not this failure path.
- `main`, line 109: any argument not equal to `--list` or `--review` (for example `--lsit`) falls through silently to the plan check and can exit 0. The docstring does not say unknown arguments are ignored.

## Notes (not findings)

- The module docstring (line 4) says the plan "describes ten scenarios". No function checks for ten. `check_plan` (lines 113 and 36-72) only reports the count it finds, so the "ten" is a description of the current plan, not a rule the gate enforces.
- `load` (lines 32-33) has no docstring and does what its name says, so there is nothing for it to misdescribe.
- No function in the file has its own docstring. Each function's behaviour was checked against the module docstring only.
