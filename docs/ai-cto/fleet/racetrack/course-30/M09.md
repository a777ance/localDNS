# M09: tools/check-cardinal.py

Source: `/home/user/localDNS/tools/check-cardinal.py` (83 lines).

Reading of the question: "silently fail" is taken as the check passing or skipping a case it should flag.

## Defects

1. **Same-cardinal duplicates pass (line 49-50).** `if t in owner and owner[t] != c:`. The check only fires when a tool sits under two different cardinals. A tool listed under two methods of the same cardinal is never flagged. CLAUDE.md §C says `.claude/cardinal-map.json` maps "every tool → one cardinal method", so the check is narrower than the contract it guards. Read two ways: the docstring (line 4) says "a tool appears under two cardinals", the CLAUDE.md contract says one method.

2. **"Implemented" is a substring test (line 28, also 40 and 67).** Line 28: `if f'"{method}"' not in matrix:`. Line 40: `if "probe" not in data[c]["methods"] or f'"{c}.probe"' not in matrix:`. Line 67: `if f'"{method}"' not in matrix:`. Any quoted occurrence of the name anywhere in `tools/matrix.py` (a comment, a usage string, a docstring) satisfies the check, even when no dispatch exists. A method that is documented but not wired passes silently.

3. **The same token is parsed two ways (line 27 vs line 66).** Line 27: `method = target.split("matrix.py ")[-1].split()[0]`. Line 66: `method = entry.split("matrix.py ")[1].split()[0]`. Where the string contains `matrix.py ` more than once, `[-1]` and `[1]` pick different tokens, so repoint targets and probe entries are validated against different method names.

4. **Boolean timeouts pass (line 57).** `if not isinstance(limit, int) or not 0 < limit <= 60:`. `bool` is a subclass of `int`, so `"timeout": true` is accepted as `1`.

5. **Docstring and code disagree on the timeout rule (line 6-7 vs line 57-58).** The docstring says a hook with "no explicit timeout (the default is 600 seconds)" fails. The code also rejects any explicit timeout above 60 (`0 < limit <= 60`), and the 60-second ceiling appears only in the message at line 58 (`between 1 and 60 s`). A reader of the docstring believes a 120-second hook passes; the code fails it.

6. **Only one settings file is read (line 52).** `settings = json.loads((ROOT / ".claude/settings.json").read_text(encoding="utf-8"))`. Hooks in any other settings file (for example `.claude/settings.local.json`) are never checked against the timeout rule, so the rule does not apply to them and nothing reports that.

7. **The "stated reason" alternative accepts anything non-empty (line 62-64).** `entry = str(probes.get(tool, "")).strip()` then `if not entry:`. A placeholder such as `"x"` or `"-"` satisfies "a stated reason", and the value is never checked to be a reason or a probe. Line 65-68 only validates entries that happen to contain `matrix.py `, so a non-matrix placeholder is never examined.

## Notes

The success line (line 77) reads `ok   {count} tool aliases across {len(CARDINALS)} cardinals, each in exactly one`. That wording is accurate only because of the narrower rule at line 49-50 (see defect 1); a duplicate within one cardinal would still print "each in exactly one".

Lines 27 and 66 raise IndexError on malformed input (an empty repoint target, or an entry that ends in `matrix.py `). That is a loud crash, not a silent pass, so it is not counted as a defect.

The mode check at line 22-23 validates that `mode` is one of three literals. It does not check that the hook in `.claude/hooks/cardinal.py` reads the same value.

The check is run with `python3 tools/check-cardinal.py` and is not executed here; every finding above comes from reading the source, not from a run.
