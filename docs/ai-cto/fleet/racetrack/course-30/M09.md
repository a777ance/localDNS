# M09 · tools/check-cardinal.py

## Defects

- tools/check-cardinal.py line 28: `if f'"{method}"' not in matrix:` tests the method name as a substring of the whole tools/matrix.py source, so a name that appears only in a comment or docstring passes as implemented. The repoint check fails silently in that case.
- tools/check-cardinal.py line 40: `if "probe" not in data[c]["methods"] or f'"{c}.probe"' not in matrix:` uses the same substring test, so a probe method mentioned only in text counts as implemented.
- tools/check-cardinal.py line 67: `if f'"{method}"' not in matrix:` repeats the substring weakness for probe entries, so a probe naming a method that is not implemented can pass.
- tools/check-cardinal.py line 45: `if text and f"`{c}.{method}`" not in text:` skips the per-method SKILL.md documentation check whenever the skill file is missing or empty. Only the single "no skill file" line on line 39 is reported, so the missing method documentation checks disappear without a message.
- tools/check-cardinal.py line 57: `if not isinstance(limit, int) or not 0 < limit <= 60:` enforces a 60 second ceiling that the docstring on line 7 does not state. The docstring says only that a hook with no explicit timeout fails, so the rule is read two ways. Line 58 then reports the 1 to 60 second range as the requirement.
- tools/check-cardinal.py line 57: `isinstance(limit, int)` is true for bool, so `"timeout": true` passes as a 1 second timeout and `"timeout": false` fails with a misleading message.
- tools/check-cardinal.py line 49: `if t in owner and owner[t] != c:` flags a tool only when it sits under two different cardinals. A tool listed under two methods of the same cardinal is counted twice on line 48 and passes silently, yet line 77 prints "each in exactly one".
- tools/check-cardinal.py line 25: `mapped = {t for c in data.values() ...}` includes tools from unknown cardinals, but the duplicate and documentation loop on lines 32 to 51 iterates only over CARDINALS. A tool shared between an unknown cardinal and a known one is never compared, and only the generic "unknown cardinals" line on line 73 is printed.
- tools/check-cardinal.py line 27: `method = target.split("matrix.py ")[-1].split()[0]` returns the bare token "matrix.py" when a repoint target has no trailing space after the name, and raises IndexError on an empty target. The first reading is checked against the wrong name, and the second is an uncaught crash instead of a FAIL line.
- tools/check-cardinal.py line 65 and line 66: `elif "matrix.py " in entry:` only validates probe entries containing the exact text "matrix.py " with a trailing space. An entry spelled differently skips validation and is accepted as a stated reason. An entry ending in "matrix.py " raises IndexError on `entry.split("matrix.py ")[1].split()[0]`.
