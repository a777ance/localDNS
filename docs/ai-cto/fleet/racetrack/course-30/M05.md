## Defects

- docs/ai-cto/loop-tick.md line 3-4: "A scheduled task starts a fresh session with this text" contradicts line 13-14: "It goes to a standing session, not a fresh one". A reader cannot tell whether the tick runs in a fresh or a standing session.
- docs/ai-cto/loop-tick.md line 8-10: "Paused 2026-11-12 ... Do not switch the task back on until the founder has attached" sits directly above line 12: "Switched on 2026-11-12 (DEC-017, GO)". Both state the loop's current state on the same date, so a reader cannot tell whether the task is on or off.
- docs/ai-cto/loop-tick.md line 22: "Confirm your checkout has the working files (git ls-files | wc -l over 100). If it does not, run git fetch origin leader && git reset --hard FETCH_HEAD." The check says "over 100" but the fallback is triggered by "does not", which reads as either fewer than 100 files or no working files. The reset also discards uncommitted local changes, and the line does not say so.
- docs/ai-cto/loop-tick.md line 33: "not DONE, not BLOCKED" names a BLOCKED status, but no format or location for that marker is defined in this file, so a tick cannot check it mechanically.
- docs/ai-cto/loop-tick.md line 41: "even one from item 1 or 2 that is not a red gate" is ambiguous. Item 1 is "A red gate or a retrofit finding", so a retrofit finding is loop work under item 1. The phrase "not a red gate" does not say whether a retrofit finding is excluded from the ratio rule.
- docs/ai-cto/loop-tick.md line 49: "Probe before each outward step." does not name which probe to run for each step, and does not say what a tick does when a probe fails.
- docs/ai-cto/loop-tick.md line 54: "Tick the item in docs/ai-cto/handoff.md with · DONE <commit>." The commit hash is not known until the Act step ships, and the Record step is written after that, so the entry either names a commit that does not yet exist or needs a second commit that the tick never plans for.
- docs/ai-cto/loop-tick.md line 57: "Run python3 tools/matrix.py orient.checkpoint. Ship that too." The output of orient.checkpoint is not described, and "Ship that too" does not name the files or the message, so the step can be run without producing a checkpoint commit.
- docs/ai-cto/loop-tick.md line 60: "No model names in any file or commit." conflicts with the session attribution rule, which requires a Co-Authored-By line that names a Claude model in every commit. The file gives no exception, so a tick cannot satisfy both.
