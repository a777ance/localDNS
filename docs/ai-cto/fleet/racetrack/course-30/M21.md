# M21 · .claude/hooks/timing.py

## Defects

- .claude/hooks/timing.py line 6 says each row holds "(time, tool, cardinal, seconds)", but line 34 names the stamp field "alias" and line 39 writes it as the third column. A reader following the docstring and a reader following the code will look for different names for the same column, so the cardinal in each row can be read two ways.
- .claude/hooks/timing.py lines 40-42: the cleanup loop calls old.stat() and old.unlink() with no guard. If another process removes a stale stamp between glob() and stat(), FileNotFoundError is raised inside the outer try. The breach context at lines 43-47 is then skipped silently, so a call over 10 seconds is recorded in the times file but never flagged to the agent.
- .claude/hooks/timing.py lines 48-49: "except Exception: pass" swallows every error. If the append at line 38 fails, the stamp was already deleted at line 35, so that call's timing is lost with no trace. A broken timing check therefore produces no output at all, and nothing shows that the 10-second check has stopped working.
- .claude/hooks/timing.py lines 32-33: when the stamp is missing, the hook returns 0 with no record. A tool call that was never stamped by the naming hook is never timed, and nothing is logged to say so, so a gap in the times file cannot be told apart from a fast call.

## Notes

The breach message at lines 45-47 gives the command "cd ROOT && python3 tools/matrix.py observe.times". This matches the usage line in the docstring at line 8, so the two instructions agree.

Line 24 keys the stamp on tool_use_id and falls back to tool_name when it is absent. Whether a PostToolUse lookup finds the stamp depends on how the naming hook writes it. That writer is .claude/hooks/cardinal.py, which this milestone did not read, so the match is not verified here.

Line 25 keeps dots in the sanitized key, so a key of ".." would resolve to the parent directory. This needs a tool_use_id of exactly that form, which is not expected in practice, so it is recorded here and not as a defect.

The 10-second cap at line 20 and the "more than 10 seconds" test at line 43 agree with each other and with the docstring at line 7.
