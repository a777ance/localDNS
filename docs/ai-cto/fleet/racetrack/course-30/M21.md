# M21 · .claude/hooks/timing.py

## Defects

- `.claude/hooks/timing.py:24` — the stamp key falls back to the tool name: `key = str(data.get("tool_use_id") or data.get("tool_name") or "unknown")`. Two concurrent calls to the same tool share one stamp. The first completion consumes it, and the second hits `if not stamp.exists(): return 0` at line 33, so that call's time is never recorded and nothing says so. Fix: key only on `tool_use_id`, or fail loudly when it is absent.
- `.claude/hooks/timing.py:34` — `started, alias = stamp.read_text(...).split("\t", 1)` raises ValueError on a stamp with no tab. The stamp is not unlinked and no row is written, and the `except` at lines 48-49 swallows it. Fix: handle the malformed stamp explicitly, and remove it.
- `.claude/hooks/timing.py:35-38` — the stamp is unlinked at line 35 before the row is written at line 38. If the append fails (permissions, disk full), the call's timing is lost and the stamp is already gone. Fix: append first, then unlink.
- `.claude/hooks/timing.py:40-42` — the stale-stamp sweep runs inside the same `try` and after the row is written. `old.unlink()` at line 42 raises FileNotFoundError when a concurrent hook has just removed that file. The exception jumps to line 48 and skips the breach message at lines 43-47, so a real 10-second breach is reported nowhere. Fix: wrap the unlink in its own try, or move the sweep after the breach print.
- `.claude/hooks/timing.py:48-49` — `except Exception: pass` drops every error silently. Each lost row, from any cause in lines 30-42, leaves `observe.times` undercounting breaches with no sign of it. The docstring at line 10 says the hook fails open, which is right for the hook's output but says nothing about lost rows. Fix: append one line to an error log before returning 0.
- `.claude/hooks/timing.py:6` against `.claude/hooks/timing.py:34` and `:39` — the docstring says each row is "(time, tool, cardinal, seconds)", but the code names the middle field `alias` (line 34 unpacks it as `alias`, line 39 writes `alias.strip()`). A reader cannot tell whether the writer stamps a cardinal or an alias, so the column means two things. Fix: use one name in the docstring and the code.
