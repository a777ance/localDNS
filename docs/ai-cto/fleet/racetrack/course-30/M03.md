# M03 · tools/check-matrix.py

Question: list every defect in this file that could make a check or instruction silently fail or be read two ways. Quoted with file and line.

## Defects

- `tools/check-matrix.py` L185–189: a failed probe is written as the `any` probe. L186 runs `mx("observe.probe", "path", "nope.txt")`, which records `FAILED` into `.claude/.matrix-probes/any` (see `tools/matrix.py` L353). No assertion after L186 checks that lanes stay closed. L189 ("any passing probe opens the lanes") then passes because the later `observe.probe path long.txt` succeeds, so the defect in `tools/matrix.py` L353 is never caught.
- `tools/check-matrix.py` L176: "check(\"act.ship is not flagged (it probes itself)\", \"EGRESS\" not in hook(\"Bash\", {\"command\": \"python3 tools/matrix.py act.ship m f --push && git push\"})[...])". The command includes a raw `git push` after `act.ship`. The assertion locks in that a raw push chained after `act.ship` is not flagged as egress, while L174 requires a bare `git push origin main` to be flagged. The test is named for `act.ship` but also enforces a gap for the raw push.
- `tools/check-matrix.py` L182: "os.utime(box / \".claude/.matrix-probes/merge\", (0, 0))". This sets up a stale probe, but no assertion uses it. The next check (L183, "a read is never egress") does not test staleness, so a stale probe is never checked.
- `tools/check-matrix.py` L234: "check(\"cap cannot be raised\", mx(\"observe.read\", \"notes.txt\", MATRIX_TIMEOUT=\"99\").returncode == 0)". The call has no sleep, so it passes at any cap. It cannot distinguish a cap of 10 from a cap of 99, so it does not test that the cap is clamped.
- `tools/check-matrix.py` L73: "check(\"confinement\", mx(\"observe.read\", \"/etc/hostname\").returncode != 0)". Any non-zero exit passes, including a missing file or a crash. The check does not verify the "FAILED: ... outside the repository" message that `tools/matrix.py` L70 produces.
- `tools/check-matrix.py` L8–14 (docstring) vs the calls in the body: the docstring says the test covers "the Matrix end to end: observe, orient, decide, act, gate modes, cap, lease, stall". No call exercises `decide.rehearse`, `decide.gate`, `decide.probe`, `orient.probe`, `orient.retrofit`, `act.ship` (only the hook's flag on it is tested), or `observe.probe merge` / `observe.probe push`. Those methods can break without this check going red.
- `tools/check-matrix.py` L66: "check(\"observe.find\", \"notes.txt\" in mx(\"observe.find\", \"*.txt\").stdout)". No return code is checked, so a crash that prints nothing fails the check, but a method that errors after printing a match passes.
- `tools/check-matrix.py` L165–166: "got.startswith(f\"cardinal: {want}\")". The prefix comparison would accept `cardinal: observe.read.anything` and any longer name beginning with the expected one, so a mis-named cardinal can pass.
- `tools/check-matrix.py` L168: "== \"cardinal: observe.read · agent: juror\"". The exact-equality check fails on any added wording, so the hook's text can change without a fault, while the test that is meant to verify the subagent name is brittle in the other direction. The two checks at L167–170 do not agree on how strict to be.

## Notes

The sandbox copy (L38–41) brings in `tools/matrix.py`, the map, and the three register files, but not the rest of `.claude/hooks/`. If `cardinal.py` imports a module that is not copied, the sandbox test fails loudly rather than silently. That was not verified by running it here.

L111–113 writes 2,100 lines to `.claude/.matrix-log` and then checks that the log is under 1,100 lines. That matches the rotation in `tools/matrix.py` L737–738 (keep the newest 1,001 lines), but the bound is loose and the test would also pass if rotation kept more than 1,000.

L220–224 (the timeout test) depends on `MATRIX_TEST_SLEEP` and a one-second cap, so it takes at least one second. The header says "about two seconds" (L16) for the whole run; that was not timed here.

L137 copies `docs/ai-cto/handoff.md` into the sandbox without a guard. If that file is missing from the repo, the test crashes with a traceback, which is loud and is not counted as a defect.

The `act.ship` method is not run by this test at all, so the gate-before-commit path in `tools/matrix.py` L674–708 has no test here. Its behaviour is covered only by the gate in the real repo.
