## Defects

- tools/check-matrix.py line 233: check("cap cannot be raised", mx("observe.read", "notes.txt", MATRIX_TIMEOUT="99").returncode == 0). No MATRIX_TEST_SLEEP is set, so the call returns 0 whether or not the cap is honored. The check cannot fail for a raised cap, so it passes vacuously.
- tools/check-matrix.py lines 229-232: "if stalls:" silently skips act.resolve (line 230-231) when no stall was recorded, and then "stall closed" (line 232, "OPEN MATRIX STALL" not in hook("Glob")) passes trivially. Line 223 flags the missing stall, but the guard and the closed check still pass with no stall to resolve.
- tools/check-matrix.py line 73: check("confinement", mx("observe.read", "/etc/hostname").returncode != 0). Any nonzero exit passes, including a Python traceback or a missing file. It never checks that the refusal was the repo-confinement refusal.
- tools/check-matrix.py line 148: check("act.edit exactly-once", mx("act.edit", "dup.txt", "x", "y").returncode != 0). It checks only the exit code and never checks that dup.txt is still "x x\n", so a crash or any other failure passes. Line 190-191 does check the file contents, so this check is weaker than its neighbour.
- tools/check-matrix.py lines 86, 92, 106, 107, 149, 185, 193, 207: each asserts only returncode != 0 for a refusal or bad-arguments case, e.g. line 92 check("act.edit bad arguments", mx("act.edit", "out.txt", "only-one").returncode != 0). A usage refusal and a crash both pass, so these cannot tell the two apart.
- tools/check-matrix.py lines 66 and 68: check("observe.find", "notes.txt" in mx("observe.find", "*.txt").stdout) and check("observe.status", "mode:" in mx("observe.status").stdout). Neither checks the exit code, and a bare "mode:" substring also matches error text, so an error can pass.
- tools/check-matrix.py line 113: check("log rotates at 2,000 lines", len(...split("\n")) < 1100). The name states a 2,000-line threshold, but the assertion accepts any log under 1,100 lines, so a rotation at 1,050 passes. The count also includes the empty string after the final newline. The name and the assertion give two different rules.
- tools/check-matrix.py lines 75 and 140: check("orient.ground", "INIT-" in ...) and check("precompact", ... "Open founder decisions: DEC-" in out ...). The sandbox copies the live docs/ai-cto/initiatives.md and docs/ai-cto/blocked.md (lines 38-39), so these checks depend on the live register having an open INIT or an open DEC. If the register is empty, the check fails for reasons unrelated to the code under test.

## Notes

The docstring at lines 2-16 lists the coverage but leaves out the probe, egress, LETTER, hard-guard, hit-rate, file-route, timing and precompact sections that the file tests further down. The docstring is therefore incomplete, though it does not misstate any check.

Line 181 sets the merge probe's mtime to epoch 0 with os.utime and makes no assertion about it. The staleness rule is only exercised indirectly by the "opening a lane with no probe is flagged" check at line 184, and the test relies on the Matrix's own probe-writing behaviour, which is not visible in this file. Lines 183, 186 and 188 likewise depend on how observe.probe writes its "any" probe, and that cannot be confirmed from this file alone.

Line 104 checks for "2 binary" in the summary, while the check name says "skips binary and big files". The assertion relies on the big file being reported under the word "binary", so the big-file skip is not asserted separately. Line 204 uses .get("additionalContext", "") while lines 202-203 use ["additionalContext"]. Both forms fail loudly, so this inconsistency does not hide a failure.
