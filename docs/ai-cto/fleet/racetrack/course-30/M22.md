# M22 · .claude/hooks/gate.sh

## Defects

- .claude/hooks/gate.sh line 18 says "Runs the repo's three static checks before any git commit", but the header at lines 19-24 lists four and the loop at lines 70-74 runs thirteen checks (check-docs, check-provenance, check-doctrine, sync-briefings, check-decisions, check-cardinal, check-matrix, check-stop-hook, check-registers, check-telepathy, check-statements, check-superfleet, check-bridge). A reader who trusts the header believes nine checks never run.
- .claude/hooks/gate.sh line 67, the commit detector `(^|[;&|[:space:]])git[[:space:]]+(-[^[:space:]]+[[:space:]]+)*commit`, misses "git -C <dir> commit" and "git -c key=val commit". The optional group only skips a dash-prefixed flag, so the directory or value after the flag stops the match, and the commit passes with no check.
- .claude/hooks/gate.sh line 67 also misses a commit preceded by "(", a backtick, or "$(", as in "(git commit -m x)" or "$(git commit ...)". Those characters are not in the leading class `[;&|[:space:]]`, so the commit passes with no check.
- .claude/hooks/gate.sh line 46, `cd "${CLAUDE_PROJECT_DIR:-.}" 2>/dev/null || exit 0`, exits 0 with no message when the directory is wrong. Every check is then skipped and the commit proceeds. The header policy at lines 34-38 accepts letting a broken hook through, but not doing so silently.
- .claude/hooks/gate.sh line 75, `[ -f "$check" ] || continue`, skips a listed check whose file is missing, without a word. If a check is renamed or deleted, the gate keeps passing and never names the gap.

## Notes

The header policy at lines 34-38 is deliberate: a broken hook lets a commit through, and a failing check blocks it. The defects above are about silence, not about that policy.

Line 64-66 says over-matching a commit inside a quoted message is intended. That is a stated choice, not a defect.

Line 45 sets `set -uo pipefail` without `-e`. That is deliberate, so a failing check reaches the `if` at line 76 and does not abort the script.

Line 79 keeps only the last 20 lines of each check's output. That can cut off a cause printed early, but the check still blocks and the reason is visible in the output. Not counted as a defect.

Line 76 treats any non-zero exit from a check as a failure, including a check that crashed. The header at lines 35-36 describes this as blocking, so it follows the stated policy. Not counted as a defect.

The gate runs only on `git commit`. It does not run on `git push` or on other writes to the tree. That matches the header and is not a defect in this file.
