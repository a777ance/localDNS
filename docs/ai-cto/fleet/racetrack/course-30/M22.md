# M22 · .claude/hooks/gate.sh

## Defects

- `.claude/hooks/gate.sh:18` against `:19-32` and `:70-74` — the header says "Runs the repo's three static checks", but lines 19-32 list four and the loop at lines 70-74 runs thirteen (check-docs, check-provenance, check-doctrine, sync-briefings, check-decisions, check-cardinal, check-matrix, check-stop-hook, check-registers, check-telepathy, check-statements, check-superfleet, check-bridge). A reader who trusts the header believes nine checks never run. Fix: state the real count, and list the thirteen in the header or point to the loop.
- `.claude/hooks/gate.sh:67` — the commit detector misses valid forms. `(-[^[:space:]]+[[:space:]]+)*` only skips flags that start with a dash, so `git -C <dir> commit` and `git -c key=val commit` do not match, because the directory or value after the flag is not skipped. It also misses commits after `(` or a backtick, such as `$(git commit ...)`, because `(` and backtick are not in the class `[;&|[:space:]]`. A commit in those forms goes through with no check. Fix: match `git` followed by any arguments up to `commit`, and add `(`, backtick and `$(` to the leading class.
- `.claude/hooks/gate.sh:46` — `cd "${CLAUDE_PROJECT_DIR:-.}" 2>/dev/null || exit 0` returns 0 when the directory is wrong. Every check is then skipped and the commit proceeds with no message. The header policy at lines 34-38 allows a broken hook to let a commit through, but it does not allow doing so silently. Fix: print a one-line warning to stderr before exiting 0.
- `.claude/hooks/gate.sh:53-62` — the payload parse ends with `|| exit 0`. If `python3` is missing or the JSON is malformed, `cmd` is empty and the commit goes through with no message. This is the policy in lines 34-38, but the gate says nothing when it gives up. Fix: same as line 46, warn on stderr.
- `.claude/hooks/gate.sh:75` — `[ -f "$check" ] || continue` skips a missing check file without a word. If a check is renamed or deleted, the gate keeps passing and never names the gap. Fix: treat a missing check as a failure, or print a warning.
- `.claude/hooks/gate.sh:79` — `tail -20` keeps only the last twenty lines of each check's output. A check that prints its cause first and its summary last can lose the cause, and the block message at lines 85-93 then shows a truncated reason. Fix: keep the first and last lines, or write the full output to a file and name it.
- `.claude/hooks/gate.sh:76` — `if ! out="$(python3 "$check" 2>&1)"` treats any non-zero exit as a failure, including a check that crashed on its own plumbing. That is the stated policy for a broken check, but it is not distinguished from a real finding. Fix: separate exit codes for "invariant failed" and "check broke".
