# M04 · tools/check-superfleet.py

Question: list every defect in this file that could make a check or instruction silently fail or be read two ways. Quoted with file and line.

## Defects

- `tools/check-superfleet.py` L83: "outside = [f for f in changed if not f.startswith(lane[\"write_area\"])]". If a lane's `write_area` is empty (or missing), every changed file starts with `""`, so nothing is reported outside the area. The review passes silently. `--review` never runs `check_plan` first (L99–108), so the empty area is not caught there either.
- `tools/check-superfleet.py` L79: "r = subprocess.run([\"git\", \"diff\", \"--name-only\", f\"origin/leader...{branch}\"], ...)". With rename detection on (the default for `git diff`), a file the lane moved out of its write area appears only under its new name, and the old path is hidden. A lane can move or delete a file outside its area and the review still passes. `--no-renames` is needed.
- `tools/check-superfleet.py` L11 vs L79: the docstring says the review compares the branch "with the branch `leader`". The code compares with `origin/leader`. A stale local `origin/leader` changes what "outside the write area" means, and the docstring does not say which ref is used.
- `tools/check-superfleet.py` L4: "The plan describes ten scenarios of 1 + N lanes." Nothing in `check_plan` (L36–72) or `main` (L109–114) checks for ten scenarios. A plan with three scenarios passes, and the success line at L113 reports whatever count it finds, so a plan that silently lost seven scenarios still reads as ok.
- `tools/check-superfleet.py` L51: "if m and f'\"{m.group(1)}\"' not in matrix:". The check is a substring search over the whole text of `tools/matrix.py`. A method name quoted anywhere in that file (a comment, a message, the usage text) satisfies it, even if the `METHODS` table no longer dispatches the method. "Names a Matrix method that tools/matrix.py implements" is checked as "appears in quotes somewhere in tools/matrix.py".
- `tools/check-superfleet.py` L65: "if not (area.startswith(HOME) and area.endswith(\"/\") and \"..\" not in area):". `HOME` is `"docs/ai-cto/fleet/"` (L29), so `docs/ai-cto/fleet/` itself passes as a write area. A lane can own the whole fleet folder. The overlap check (L68–71) catches it only when a second lane exists, so a one-lane plan with that area passes.

## Notes

The duplicate-id check (L40–41), the scenario-id format (L44–45), and the lane `covers`/`done_when` check (L63–64) all work as written. The write-area overlap check (L68–71) uses `startswith` on paths that all end in `/`, so the example folder a under the fleet area and the example folder ab under the fleet area do not overlap, which is correct.

The `review()` function reports "changed nothing" (L85–86) only when the diff is empty, so a branch with commits that are all empty commits is reported as changed nothing, which is right. It does not check for uncommitted changes in a working tree, because the review compares committed branch refs only. That is a stated limit of the design, not a defect.

`load()` (L32–33) and `review()` (L76) index `["scenarios"]`, `["id"]`, and `["lanes"]` directly. A malformed plan raises `KeyError`, which is loud and not silent.

`check_plan` does not verify that `.claude/superfleet.json` exists before reading it (L28, L33). The read raises a traceback if the file is missing. That is loud.

The look-first check (L49–57) accepts a Matrix method or a check name but not both missing, and it does not verify that the named method is runnable as lane 0 (only that the name appears in the file). The result is the same defect as L51, not a separate one.
