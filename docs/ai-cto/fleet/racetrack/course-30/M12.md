# M12 · tools/check-provenance.py

## Defects

- tools/check-provenance.py line 65: the tag pattern excludes ">" from the body class "[^\n>]*?". A tag whose body holds an ASCII arrow, such as "verify: a -> b", fails to match at all at that position, so the tag is skipped with no failure and no warning.
- tools/check-provenance.py line 65: the gaps after the comment marker and after the keyword use "\s*", which crosses newlines under MULTILINE, and the bare "#" alternative matches a "#" anywhere on a line, including mid-prose and URL fragments. The same text is read as a tag or not depending on line breaks and position.
- tools/check-provenance.py line 97: "if m and (REPO / m.group(1)).exists():" silently drops every deploy-target row whose path is missing from the repo. A typo or rename in the section C table shrinks the target set and the coverage denominator, and nothing is reported.
- tools/check-provenance.py lines 70, 71, 80 and 82: SCAN_SUFFIXES has no entry for extensionless files or for suffixes such as ".example", and SKIP_DIRS excludes ".github". The section C targets "unbound-cache-dump", "unbound-cache-load" and the ".env.example" files are kept as targets by line 97 but can never be scanned, so under --strict line 188 reports them as untaggable with no way to satisfy the check.
- tools/check-provenance.py lines 146-147: "if rel == str(SELF): continue" exempts the whole file from the scan, not only its examples. A real tag written into this file is never validated or counted.
- tools/check-provenance.py line 109: "tier = parts[0].upper()" folds case silently, so a lowercase tier letter is accepted and enforced as uppercase. The docstring and the TIERS table use uppercase letters only, so the two readings disagree with no message.
- tools/check-provenance.py lines 123-126: "if ':' in p:" discards any field after the third part that has no colon, with no error. A verify route that continues after a separator dot loses its tail silently, and a non-verify field without a colon is also dropped.
- tools/check-provenance.py line 161: "tagged[rel] = fields" overwrites the entry for each tag in the same file. Only the last tag reaches the coverage count and the printed summary (lines 190-192 and 199), while every tag is still validated at lines 157-176. The summary and the validation disagree.
- tools/check-provenance.py line 172: "if rel not in queue:" is a substring test on the whole text of docs/DEPLOY-QUEUE.md. A target counts as staged when any longer or unrelated path containing it appears anywhere in that file, including in a closed or struck-through entry.
- tools/check-provenance.py lines 149-151: "except UnicodeDecodeError: continue" skips a file with no failure and no warning, so any tag in a non-UTF-8 file goes unchecked and invisible.
- tools/check-provenance.py lines 207-210: when no tag is found at all, the check prints "All 0 provenance tag(s) valid." and exits 0. An empty or mis-scanned tree passes vacuously.

## Notes

The check reads docs/DEPLOY-QUEUE.md once per tagged file inside the loop at line 171. This is wasted work, not a defect.

Coverage of deploy targets is enforced only under --strict (lines 186-188), which matches the docstring (lines 37-38) and its incremental-adoption intent.

The future-date test at lines 119-120 uses the local clock through dt.date.today(). A machine with a skewed clock can accept or reject a date on the wrong side of today.

Line 115 uses dt.date.fromisoformat, which accepts compact forms on newer Python versions, while the error message at line 117 says the date must be ISO YYYY-MM-DD. The message and the parser disagree, but the failure mode is a looser accept, not a silent pass of a bad date.

Line 206 prints a non-ASCII cross mark to stderr. This works under UTF-8 locales and Python 3.7 and later, but could fail under a legacy ASCII locale.

Lines 52 and 74 depend on __file__ resolving to a path under REPO for relative_to to succeed. This holds on the supported Python 3.9 and later path.

Every finding comes from reading the source. The check was not executed and no tag was run through the parser.
