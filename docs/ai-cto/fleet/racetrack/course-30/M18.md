# M18 · tools/racetrack.py

## Defects

- tools/racetrack.py lines 92-93, "except OSError:" / "pass": a failed git call is swallowed, so the outside-write list stays empty and the run reads as clean. A missing git binary can make a dirty tree pass silently.
- tools/racetrack.py line 88, "out = subprocess.run([\"git\", \"status\", \"--porcelain\"], cwd=root, capture_output=True, text=True).stdout": the return code is never checked. A non-zero exit (for example, root is not a git repository) gives empty stdout, which is read as no outside writes.
- tools/racetrack.py lines 88-91: the check runs git status over the whole working tree, not over this run. Files already dirty before the run outside the mode folder are reported as outside writes, and writes already committed are never seen. Renamed entries carry the text "old -> new" in ln[3:], so the path is misreported.
- tools/racetrack.py line 90, "if \"docs/ai-cto/fleet/racetrack/\" not in ln[3:]": this is a second hard-coded copy of the folder that TRACK on line 21 already defines. If the folder moves, the exclusion stops matching and every mode run reads as writing outside its area.
- tools/racetrack.py line 76, "file_bullets = [ln for ln in text.splitlines() if ln.startswith(\"- \")]": only column-zero hyphen bullets are counted. Star bullets and indented bullets are not counted, so the Count check can pass when the findings are wrong. The count also does not check section, so a bullet under Notes is counted as a defect.
- tools/racetrack.py line 24, "COUNT = re.compile(r\"^Count:\\s*(\\d+)\", re.MULTILINE)", with line 72, "m = COUNT.search(text)": only the first Count line is read. A second Count line in the same file is ignored with no problem reported.
- tools/racetrack.py line 80, "for path, s, e in citations(text):": every citation in the whole file is checked, including prose and code blocks. The docstring on lines 4-5 says only findings are checked. A citation-shaped string outside the findings can fail a clean run, and the scope a reader expects is not the scope the code enforces.
- tools/racetrack.py line 43, "a citation with no directory is matched by name: it resolves only when exactly one tracked file has that name", with line 48, "hits = [p for p in root.rglob(path) if \".git\" not in p.parts and p.is_file()]": the docstring says tracked files, but rglob walks the working tree, including untracked and ignored files. A name can become ambiguous, or resolve, depending on local state.
- tools/racetrack.py line 11, "Exit 0 when every citation resolves and the counts match, 1 otherwise": the exit also depends on outside writes, which main checks on line 130. A reader of the docstring can believe exit 0 covers the write check when it does not.
- tools/racetrack.py lines 109-111, the selftest: it covers only a citation past the end of its file. It does not exercise the bullet count (line 76), the name-only lookup (line 48), or the outside-write check (lines 88-93), so those silent-pass paths are never tested.

## Notes

The citation regex on lines 22-23 handles both "path:N" and "path lines N-M" forms, and the group indexes on lines 30-33 match it. The harness exclusion on line 39 is correct for the scorer's own file.

The line count on line 59 uses splitlines(), which also breaks on form feeds, vertical tabs and similar characters that editors and sed -n do not count as line ends. A citation can therefore resolve against a different line than the reader sees. This is worth a separate check, not a fix here.

Line 59 reads with errors="replace", but line 71 reads the findings with no error handling. A non-UTF-8 findings file stops the run with a traceback rather than being scored. That is loud, so it is not counted as a defect.

The mode name on line 122 is joined to TRACK without validation, so an argument with ../ would read outside the racetrack folder. The user runs this tool, so this is a note, not a defect.
