# M10 · tools/check-docs.py

## Defects

- tools/check-docs.py line 452-454: the glob `**/*.md` with default settings never descends into dot-directories, so every Markdown file under `.claude/` (agents, commands, output styles, factory tasks) is silently never checked. The filter on line 453 that excludes `.git` is dead code for the same reason. The docstring on line 4 says "every `*.md` file in the repo".
- tools/check-docs.py line 126 and line 187: the repo-path test `REPO_TOP` (lines 45-48) has no dot-directory entry, so inline-code references such as `.claude/hooks/gate.sh` are never verified and pass silently, even when they dangle.
- tools/check-docs.py line 114-116: a glob token (one containing `*`) passes as long as its parent directory exists, without checking that the pattern matches any file. A pattern such as `docs/*.nothing` passes silently, and a bare `*` passes because the base directory always exists.
- tools/check-docs.py line 408-412: if `04-user-services/ai-orchestration/...` exists but `docs/bifrost.html` is missing, the glyph comparison for the page is skipped with no problem reported. Line 402-404 reports a missing source file, so the two cases are read differently.
- tools/check-docs.py line 415-418: if `CLAUDE.md` is missing, or the backbone regex on line 417 fails to match (for example, when the Backbone bullet is the last bullet and no following `- **` exists), the CLAUDE.md §H glyph surface is dropped with no problem reported.
- tools/check-docs.py line 330-332: `GLYPH_HTML` uses `<td class="glyph">(.*?)</td>.*?<td class="arch">` with `re.S`. If a row has a glyph cell without a matching arch cell, the non-greedy match pairs that glyph with the next row's archetype, so a glyph is silently assigned the wrong role.
- tools/check-docs.py line 85-91 and line 98-106: fence detection recognises only triple-backtick fences (`^\s*```). A `~~~` fenced block is treated as prose, so headings inside it become anchors (a broken anchor link can pass silently) and links inside it are checked as if live.
- tools/check-docs.py line 383: the table row is split with `split("|")`, which ignores an escaped `\|` inside a cell. The row is then misread, and line 384-385 silently drops any row with fewer than five cells, so a glyph can vanish from the canonical table with no report.
- tools/check-docs.py line 387: the separator-row skip list (`"---", ":--"`) does not match an aligned separator such as `:---:`. That row is recorded as a glyph called `---`, so the check reports a false "defined in ..., absent from ..." failure.
- tools/check-docs.py line 389 versus line 427: duplicate glyph rows in the §1 table are resolved last-wins (`table[glyph] = archetype`), while the CLAUDE.md surface is first-wins (`brief.setdefault(...)`, with a comment explaining why). The same source text can therefore be read two ways depending on the surface.
- tools/check-docs.py line 438-445: the glyph comparison runs only for glyphs present in the canonical table (`set(canon) - set(table)`) and in both (`set(canon) & set(table)`). A glyph that exists only on another surface is never compared and is ignored silently.

## Notes

The docstring on lines 2-30 describes the intended behaviour; the defects above are where the code departs from it. The file's own design choices, such as the paragraph scoping in candidate_tokens (lines 129-148), the ALLOW_MISSING list (lines 61-67), and the narrow first-word role comparison (lines 324-329), are deliberate and are not counted as defects.

The ROLE_ALIAS map on line 335 (`compliance` mapped to `weigh`) cannot be verified from this file alone. Whether that alias is correct depends on the wording of the three glyph surfaces, which this milestone did not read, so it is not counted.

The LEGACY pattern on lines 53-57 was checked against the current top-level folders (01-core-network, 02-performance, 03-monitoring, 04-user-services) and does not produce a false match on any of them.
