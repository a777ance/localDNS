# M13 · tools/check-registers.py

## Defects

- tools/check-registers.py line 26: the heading pattern only matches "## INIT-NNN · " and "## DEBT-NNN · " with exactly three digits. A heading written any other way (a "### " level, an em dash instead of "·", a four-digit id such as INIT-1000) is skipped without a FAIL. Line 51 then prints "ok ... each with a valid status, unique, newest first" over only the headings that matched, so a malformed entry passes silently and is also invisible to the duplicate check (line 30) and the ordering check (line 32).

- tools/check-registers.py line 39: the body of each entry runs from its heading to the next register heading, or to the end of the file for the last one. A Blocked entry therefore takes its DEC or blocked.md reference from any later "## " section in the same file (for example a trailing Notes section), not only from its own text. The check can pass for a Blocked entry that names nothing.

- tools/check-registers.py line 40: the pattern "DEC-\d{3}|blocked\.md" accepts any DEC-NNN token, without checking that the id exists in docs/ai-cto/blocked.md, and it has no word boundary, so a longer token such as DEC-0123 also matches. A Blocked entry that cites a non-existent or mistyped DEC id passes, although the docstring at lines 7-8 says the point is that a reader can tell what would unblock it.
