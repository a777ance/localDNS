# M11 · tools/check-doctrine.py

## Defects

- tools/check-doctrine.py line 121-126: the "sent" payload is collected by walking the whole module tree for any json.dumps call with a dict literal, not only the FireworksSampler request. Quote: "if isinstance(node, ast.Call) and isinstance(node.func, ast.Attribute) and node.func.attr == \"dumps\"". A key sent by any other function in jury.py counts as pinned, so the check can pass while the sampler sends nothing.
- tools/check-doctrine.py line 124-126 and 163-166: the sent value is recorded in sent[k.value] = v but never compared with the stated doctrine value. Quote: "if key not in sent:". A payload carrying "temperature": 2.0 or "top_k": 400 passes silently. Only key presence is asserted.
- tools/check-doctrine.py line 128-137: CLI flags are collected from every add_argument call in the file into one dict, and a later call overwrites an earlier one. Quote: "cli[flag] = v". A flag in another parser can shadow the real one.
- tools/check-doctrine.py line 168: "if key in cli and cli[key] != want:" skips the comparison when the CLI flag is absent. Quote: "if key in cli and cli[key] != want". Removing or renaming --temperature, --top-p, --top-k or --max-tokens passes silently.
- tools/check-doctrine.py line 96-103 with line 117-118 and 135-136: _const returns None for any non-literal default, and the caller drops it without a message. For a CLI default this is a silent pass. For a constructor default the failure reads as "no default", which hides that the default is a non-literal expression.
- tools/check-doctrine.py line 173-177: the penalty clause checks only the value stated in CLAUDE.md (stated.get(key) not in (0, 0.0)). It never reads presence_penalty or frequency_penalty from jury.py, so the code-side pin is unchecked. This contradicts the docstring at lines 22-25, which says the penalties are "pinned to 0 AND actually sent".
- tools/check-doctrine.py line 26-27 and 168: the docstring says the check covers "the CLI defaults matching the constructor defaults". Line 168 compares the CLI default with the doctrine value (want), not with the constructor default. The two readings differ, and the code matches only the doctrine reading.

## Notes

The first-match semantics of re.search at lines 82, 87 and 60-65 are safe only while §G states each value once. A later restatement with a different number would be ignored without a warning. This is a risk to watch, not a current defect.

The exemption for jury-claude in the docstring at lines 36-39 is deliberate and stated in the file, so it is not a defect.

The bool case in _const at line 98 (isinstance(True, int) is true) is a theoretical issue only, because no sampler default is a bool. It is not counted as a defect.

The pass message at lines 189-194 is accurate. It says a green run is not a claim that the posture clauses were followed.
