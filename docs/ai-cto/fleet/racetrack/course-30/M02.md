# M02 · tools/matrix.py

Question: list every defect in this file that could make a check or instruction silently fail or be read two ways. Quoted with file and line.

## Defects

- `tools/matrix.py` L13 vs L470–476: the usage line documents `decide.probe [FILE...]` as "the fast gates only". `decide_probe(*args)` ignores every argument except to test for a single argument with a space, and then runs `bad = _fast_gates()` at L474 regardless of the files named. A caller who names files gets a probe that silently checks something else.
- `tools/matrix.py` L472–473: "if len(args) == 1 and \" \" in args[0]: return decide_rehearse(args[0])". A file path containing a space is rehearsed as a shell command, not probed. Read two ways: the usage line (L13) says FILE, the code says "command if it has a space".
- `tools/matrix.py` L37 vs L243–244: the docstring says "Paths are confined to the repository." `act_edit` reads the `--old-file` and `--new-file` arguments with `Path(rest[...]).read_text(...)` and never calls `inside()`, so those paths are not confined.
- `tools/matrix.py` L96: "b = int(end) if end else (len(lines) if start else min(len(lines), PAGE))". With START and no END, `observe.read` prints from START to the end of the file, while L4 says "(first 200 lines unless a range is given)" and L100 prints a "Next:" hint that assumes paging. START alone is read as "to end" by the code and as an unbounded range by the docs.
- `tools/matrix.py` L353: "(d / \"any\").write_text(line, encoding=\"utf-8\")  # lane 0 ran: any probe counts before lanes are opened". The `line` written here (L351) starts with `FAILED` when `ok` is false, but `any` is written regardless. A failed probe therefore opens the lanes, which the hook treats as "any passing probe". The comment says "any probe counts", and the hook reads that as "any passing probe".
- `tools/matrix.py` L452–453: "if cp.exists() and head and not _git(\"log\", \"-5\", \"--format=%h\", \"--\", \"docs/ai-cto/checkpoint.md\").stdout.strip():". `git log -5 -- PATH` lists the five most recent commits that touched PATH, so any file with history yields output and the warning never fires. The check written as "touched in the last five commits" is never true for a tracked checkpoint, so a stale checkpoint is never reported.
- `tools/matrix.py` L329–335: `lease = re.search(...)` falls back to `'none recorded'` when `handoff.md` does not match. `orient_checkpoint` then writes "**Lease:** none recorded" into the live block without any warning. A format change in `handoff.md` silently erases the lease from the checkpoint.
- `tools/matrix.py` L631: "tip = _git(\"rev-parse\", \"--verify\", f\"origin/{TRUNK}^{{commit}}\").stdout.strip() or rev". If `origin/leader` is not known, `tip` silently becomes the `--at` revision. The rehearsal then sets the throwaway remote's `leader` to that revision, and the check at L650 compares `seen` with `tip` and passes trivially. The command is rehearsed against a state that is not the remote's real state, with no warning.
- `tools/matrix.py` L655: "s = run(\"bash\", \"-c\", setup, cwd=work, env=env, timeout=60)". `subprocess.TimeoutExpired` is not caught here, unlike the command run at L658–662. A slow `--setup` produces a Python traceback instead of a `FAILED:` line, and the rehearsal's `finally` runs without a rehearsal record.
- `tools/matrix.py` L618–626: `--at` or `--setup` given as the last argument makes `rest[i + 1]` raise `IndexError`, which is not caught and does not produce the `FAILED:` usage message the code at L628 is meant to give.
- `tools/matrix.py` L693 and L696: "r = _git(\"add\", \"--\", *files)" then "r = _git(\"commit\", \"-q\", \"-m\", message)". `act_ship` never checks the index before committing, so anything already staged by an earlier command is committed with these files. L678 says "Nothing is staged implicitly", which is not true of the index.
- `tools/matrix.py` L598: "print(\"gates: the nine checks in decide.gate audit all stored state on every commit\")". The gate globs `tools/check-*.py` (L212, L681), which matches twelve files in the repo now. The printed count is a hard-coded claim, not a measurement.
- `tools/matrix.py` L555–556: "if \"Not rehearsed:\" in text: continue". If the phrase appears anywhere in `docs/ai-cto/roadmap.md`, the whole file is skipped, so an unrehearsed command elsewhere in the file passes the audit silently.
- `tools/matrix.py` L529: "return re.findall(r\"```bash\\n(.*?)```\", text, flags=re.DOTALL)". Only fences opened as exactly ` ```bash` followed by a newline are read. A `sh`, `shell`, or indented fence is skipped without a finding, so `audit_cd` and `audit_rehearse` pass over those blocks silently.
- `tools/matrix.py` L532–534: `audit_cd` flags only `cd /home/user/`. The rule it enforces (`CLAUDE.md` L53, "Commands start with `cd ~/localDNS`") also requires the `cd ~/localDNS` opening. Nothing checks for it, so a bash block without that opening passes the "COMMAND CD" audit.
- `tools/matrix.py` L742: "cap = min(CAP, int(os.environ.get(\"MATRIX_TIMEOUT\", str(CAP))))". `MATRIX_TIMEOUT=0` gives `cap = 0`, and L766 calls `signal.alarm(cap)`, which with 0 cancels the alarm. The 10-second cap is silently switched off. A non-integer value raises `ValueError` before the `try` block.
- `tools/matrix.py` L773–774: "except TypeError: sys.exit(f\"FAILED: wrong arguments for {name}. ...\")". Any `TypeError` raised inside a method (a bug, not a bad argument) is reported as bad arguments, which points the operator at the wrong fix.
- `tools/matrix.py` L774: the message points to "python3 tools/matrix.py --help", but L722–724 print only the list of method names, not usage. The reader is sent to a help text that does not exist.
- `tools/matrix.py` L427–428: "sys.exit(\"FAILED: observe.probe takes: push  |  merge BRANCH [BASE]  |  path PATH\")". The usage omits `goal`, which L10 documents and L393 dispatches. The message misstates the accepted arguments.
- `tools/matrix.py` L386: "observe_probe(\"merge\", branch, \"leader\")". The name `leader` is hard-coded here, while `TRUNK` (L64) and L401 use the constant. If `TRUNK` changes, the goal probe still merges into `leader`.
- `tools/matrix.py` L188: "med = lambda s: sorted(s)[len(s) // 2]". For an even count this returns the upper middle value, not the median the output column is labelled with (L193).
- `tools/matrix.py` L442: "(r.stdout + r.stderr).strip().splitlines()[-1][:140]". A failing fast gate that prints nothing raises `IndexError` in `_fast_gates`, so the probe crashes instead of reporting `FAIL`.
- `tools/matrix.py` L765–766: "if name not in (\"act.ship\", \"decide.gate\", \"decide.rehearse\", \"decide.probe\", \"act.probe\"): signal.alarm(cap)". Five methods are exempt from the 10-second cap on the grounds that "each step is timed instead". `act_ship` then sleeps up to 30 seconds (L702) before failing, and no per-step timing for it is written in this file.

## Notes

`observe_status` (L300–310), `orient_ground` (L202–207), and the `act_undo` restore (L258–266) work as written. `act_undo` does not back up the file it overwrites, so an undo cannot itself be undone. That is a design gap, not a silent failure, and it is not listed as a defect.

`probe_goal` (L368–388) runs the push probe and then the merge probe. `observe_probe` exits on a failed push probe (L429–430), so the merge probe never runs and the goal reports only the first failure. That is by design.

`probe_push` (L356–365) matches porcelain lines by their first character. It is accurate for `git push --dry-run --porcelain` as documented by git, but it was not run here to confirm the output format on this git version.

`orient_probe` (L446–467) also reads `blocked.md` without a guard (L460). A missing file raises an exception rather than being reported. That is loud, so it is not counted as silent.

The decide.gate and act.ship paths run the checks in parallel (L682–683). The concurrency was not exercised here.
