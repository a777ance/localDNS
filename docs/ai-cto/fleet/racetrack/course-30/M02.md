# M02 · tools/matrix.py

## Defects

- `tools/matrix.py` line 3 and line 95: the usage line says observe.read shows "first 200 lines unless a range is given", but `b = int(end) if end else (len(lines) if start else min(len(lines), PAGE))` makes `observe.read PATH START` with no END print from START to end of file, with no "more lines" hint (line 98 needs `not end`). The documented and actual behavior differ silently.
- `tools/matrix.py` line 96: `for i, line in enumerate(lines[a - 1:b], a)` has no lower bound on START. `observe.read PATH 0 10` slices `lines[-1:10]` and prints an empty or wrong range with no error.
- `tools/matrix.py` line 327: `if kind == "check" and running: sys.exit(1)`. The docstring (lines 307-308) says check fails closed, but any other kind (a typo, or "Check") falls through to the status branch and returns 0. The gate that reads this exit code passes.
- `tools/matrix.py` line 314: `fh.write(f"launch\t{args[0] if args else '?'}\n")`. A launch with no ID is recorded as "?", which `finish` cannot match, so the running count never clears and the check fails with no clean way to resolve it.
- `tools/matrix.py` line 336: `def observe_factory(kind="next", *args):`. Any unrecognized kind (for example a typo of "spent" or "done") silently falls through to the "next" branch and prints the next queue id.
- `tools/matrix.py` line 420: `(d / "any").write_text(line, encoding="utf-8")  # lane 0 ran: any probe counts`. "any" is written even when `ok` is False (line 418 writes "FAILED"). CLAUDE.md requires "a fresh passing probe" before a push, merge, or new agent, so a failed probe satisfies a check that reads only "any".
- `tools/matrix.py` line 14 and line 6: the usage says `act.probe` and `observe.probe push` "change nothing". Both call `_record_probe` (lines 418-420, reached from line 431 via `probe_push` and line 570 via `act_probe`), which writes `.claude/.matrix-probes`.
- `tools/matrix.py` line 475-477: `clean = _git("merge-tree", "--write-tree", onto, tip).returncode == 0`, then `'no conflicts' if clean else 'CONFLICTS'`. Any nonzero exit counts as a conflict, including a usage error from git older than 2.38 (which lacks `--write-tree`). The probe then reports CONFLICTS for a branch that has none.
- `tools/matrix.py` line 509: `f"{name}: {(r.stdout + r.stderr).strip().splitlines()[-1][:140]}"`. A fast gate that exits nonzero with no output raises IndexError here. The crash happens before `_record_probe` (line 542), so the stale "decide" probe record stays and reads as current.
- `tools/matrix.py` line 539-541: `if len(args) == 1 and " " in args[0]: return decide_rehearse(args[0])`, then `bad = _fast_gates()`. A single FILE argument containing a space (for example a file named in the docs folder (its name has a space)) is run as a shell command in a rehearsal copy. Also, any FILE arguments otherwise are ignored: `_fast_gates()` takes no arguments, though the usage line 12 says `decide.probe [FILE...]`.
- `tools/matrix.py` line 622-623: `if "Not rehearsed:" in text: continue`. One "Not rehearsed:" line anywhere in `docs/ai-cto/roadmap.md` silently exempts every command block in the file, not just the one it marks.
- `tools/matrix.py` line 698: `tip = _git("rev-parse", "--verify", f"origin/{TRUNK}^{{commit}}").stdout.strip() or rev`. If `origin/leader` is not fetched, the tip silently becomes the `--at` revision. The later check at line 717 (`seen != tip`) then always passes, and the output (line 730) reports "remote leader at" a commit that is not the remote's.
- `tools/matrix.py` line 745 and line 763: the error at line 745 says "Nothing is staged implicitly", but line 760 stages only the named files, and line 763 `_git("commit", "-q", "-m", message)` commits the whole index. Anything already staged is committed under the message.
- `tools/matrix.py` line 832: `cap = min(CAP, int(os.environ.get("MATRIX_TIMEOUT", str(CAP))))`. Setting `MATRIX_TIMEOUT=0` gives cap 0, and line 856 `signal.alarm(cap)` then disables the alarm. There is no lower bound, so the 10-second cap is removed without any message. A negative value crashes at line 856 instead.
- `tools/matrix.py` line 855: `if name not in ("act.ship", "decide.gate", "decide.rehearse", "decide.probe", "act.probe"): signal.alarm(cap)`. These five methods are exempt from the cap, yet the usage at line 38 says "Hard cap: 10 seconds per call". Their subprocess calls have no timeout (line 213 `decide_gate`, line 507 `_fast_gates`, line 560-561 `act_probe` ship, line 749-750 `act_ship`), so a hung gate or a hung `git push --dry-run` blocks with no cap and no lease.
- `tools/matrix.py` line 863-864: `except TypeError: sys.exit(f"FAILED: wrong arguments for {name}...")`. This catches any TypeError raised inside the method body, not only argument-count errors, so a real bug is reported as a usage error.
- `tools/matrix.py` line 382, line 397, and line 527: the same open-decision regex is written three times, `^- \*\*(DEC-\d{3}) · (.*?) · OPEN\*\*`. It matches only a bulleted "- **DEC-NNN · ... · OPEN**" line. A decision written in the CLAUDE.md tile form (`**DECISION · DEC-NNN · ...**`) is invisible to all three, and `decide.open` then prints "no open decisions" with no error.
- `tools/matrix.py` line 235: `target.write_text(sys.stdin.read(), encoding="utf-8")`. Empty or missing stdin (for example a failed heredoc) silently truncates the target file to empty. The `.claude/.matrix-bak` copy from line 233 makes it recoverable, but nothing reports the empty write.
- `tools/matrix.py` line 3-32 (usage block) and line 801 (METHODS): the usage block omits `observe.hitrate`, `observe.agents`, and `observe.factory`, all of which METHODS accepts. These methods are reachable only through `list` or by reading the code.

## Notes

The `observe.agents` launch and finish records are plain text in `.claude/.agent-ledger`, and `observe.agents status` reads the whole file each time. This is fine at the current scale, but it is not a defect.

The `act_resolve` function (line 287) raises IndexError if the stalls log (written only when a stall is resolved) exists without the `---` marker. This is a loud crash, not a silent failure, so it is not counted as a defect.

The retrofit footer at line 665 hard-codes "the nine checks in decide.gate", while `decide_gate` (line 211) runs every `tools/check-*.py` it finds. The count is a claim to keep in sync, not a logic error.

The `audit_rehearse` check (line 620) reads only `docs/ai-cto/roadmap.md`. A command handed to the founder in another doc is not rehearsal-audited. This is a scope limit, stated here rather than counted as a defect.

The `probe_goal` pattern at line 441 matches any goal that contains the word "send" or "publish", so it runs the push dry-run for goals that are not egress. The dry-run changes nothing, so this costs time but does not fail a check.

The `observe.search` path reads with `read_text(encoding="utf-8")` and no `errors="replace"` (line 121). A decoding error skips the rest of that file and counts it as skipped (line 128-129), which the summary line at line 131 reports.
