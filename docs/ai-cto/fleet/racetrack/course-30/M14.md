# M14 · tools/check-stop-hook.py

## Defects

- tools/check-stop-hook.py line 75-78: run() never checks the hook's return code. If the hook crashes on a valid reply, stdout is empty and run() returns "", which the case loop reads as allow. The fail-open case at line 134 has the same blind spot, so a traceback and a deliberate allow look identical.
- tools/check-stop-hook.py line 145: the RETROFIT table is cut with split("}", 1)[0], which stops at the first closing brace inside the table. If "RETROFIT = {" is missing, [-1] returns the whole of tools/matrix.py, and the check at line 147 then passes any key that appears anywhere in that file.
- tools/check-stop-hook.py line 139: the enforcement check looks for the quoted prefix "{key}, so it matches any key that begins with the rule name (for example TILE inside a longer key). It does not prove the hook enforces that exact rule.
- tools/check-stop-hook.py line 141: the output-style check is a substring match against the whole briefing.md. The phrase "scratchpad" at line 60 is a common word, so it passes if it appears anywhere in the style, not in the rule text. Short phrases such as "Landed · N =" at line 61 have the same weakness.
- tools/check-stop-hook.py line 149: the tested set is hand-typed, with SCRATCHPAD, LANDING, NEXT ACTION, L ITEMS OPEN and L STEP listed as tested. It is not derived from the assertions that actually run, so a rule still counts as tested after its test is removed.
- tools/check-stop-hook.py line 115: the L-item check reads only the last paragraph of the reply (got.split("\n\n")[-1]) when it asserts that DEC-900 is not handed to a sub-loop. A DEC item that leaks into an earlier paragraph passes.

## Notes

Line 20 builds the code fence from three backticks so the file never contains one; that is intentional and not a defect.

Line 46 allows the word "probably" on purpose, since the style bans only the vague hedges it names. The check at line 43 covers "should work" and does not need to cover every hedge.

Lines 98 to 108 set MATRIX_SCRATCH_DIR in the process environment and remove it at line 108. If an assertion between them raised, the variable would leak into later runs, but the script exits on the first error, so the leak has no effect here.

The docstring at lines 2 to 9 says the script asserts which rule blocked. The code checks only the start of the reason at line 96, which is enough for the rule keys in use, but it is looser than the docstring reads.

Line 134 runs the hook without CLAUDE_PROJECT_DIR. That is harmless for malformed input, but the same missing return-code check from the first defect applies to it.
