# M16 · tools/check-telepathy.py

## Defects

- tools/check-telepathy.py line 81: check("alice cannot read bob's mail", call(env, "alice", "read", id=mid)[0] is None). This passes for any error the server returns, not only the access refusal. A read that fails for an unrelated reason (a bad id, a server fault) still satisfies the check, so a broken access control can go unnoticed.
- tools/check-telepathy.py line 82: check("a bad mailbox name is refused", call(env, "alice", "send", to="../x", body="b")[0] is None). Same weakness. Any error passes. The check does not show that the "../x" name caused the refusal, and the call omits the subject argument that line 62 supplies.
- tools/check-telepathy.py line 36: return (None, text) if result.get("isError") else (json.loads(text), ""). A successful call whose result is JSON null also returns None, the same value as an error. Lines 81 and 82 then read a null success as a refusal, so the two cases are read the same way.
- tools/check-telepathy.py line 61 against lines 65 to 67: line 61 sets t0 "so it includes the sender's start-up", and line 67 uses t0 for the reported time. The enforced 2 s window on line 65 starts only after call(...) returns on line 62, so the send is not inside the window. The check label on line 66 ("within 2 s") and the docstring on line 6 ("within 2 s") describe a stricter test than the one that runs.
- tools/check-telepathy.py line 48: if want in line: return True, seen. This is a substring match, and lines 59 and 65 use it. The "armed" check on line 59 passes on any watcher line containing the word, including an error line that mentions arming. The "NEW {mid}" check on line 65 passes on any line that contains that text, such as a longer id that begins with the same characters.

## Notes

The readline call at line 46 sits behind select at line 43. Python's text stream can buffer a second line that select on the file descriptor cannot see, so the wait on line 65 can time out and report "nothing printed" on a run where the line did arrive. The failure is loud (FAIL on line 66) and intermittent. The PYTHONUNBUFFERED setting on line 55 applies to the child watcher, not to this parent-side buffer.

When the watcher closes its stdout, readline at line 46 returns an empty string and select keeps reporting the stream as ready. The loop at lines 42 to 49 then spins until the deadline and returns False with no sign that the watcher exited. The result is a delayed "nothing printed" failure, not an immediate report of a dead watcher.

Several failures end the run with a traceback rather than a FAIL line. Line 34 indexes "result" from json.loads of all of stdout, so any extra output or a JSON-RPC error object raises. Line 80 indexes messages[0] and status, so an empty inbox raises IndexError. Line 33 sets timeout=10, so a slow server raises TimeoutExpired. In each case the FAILS list collected so far is not printed, because line 83 is not reached. These are loud failures, so they are not counted as defects.

The check helper at lines 24 to 26 omits the detail text when detail is falsy. A failed check whose detail is an empty list or None prints only its name. This affects reporting only.

Line 8 states that the real mailbox at the user's state directory is never touched. The file sets TELEPATHY_DIR on line 55 and nothing else. Whether the MCP server and the watcher honor that variable alone is not shown in this file, so the claim is not verified here.

Line 9 says the test is Linux only, because the watcher uses inotify. The file has no platform guard. On another platform the watcher fails to arm, and line 59 reports that as a watcher failure, not as a skipped test.

The end-to-end sequence on lines 56 to 81 (send, watch, inbox, read, mark done) matches the docstring on lines 4 to 6. Each step is asserted through check, and the failures print at the end on lines 83 to 84. The watcher is killed and waited on in the finally block on lines 68 to 70, and TemporaryDirectory on line 54 removes the mailbox directory.

The MCP server (tools/telepathy/telepathy_mcp.py) and the watcher (tools/telepathy/watch.py) were not read for this report. Their output formats, error text, and any initialize requirement are therefore unverified here.
