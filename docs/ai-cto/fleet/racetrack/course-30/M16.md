# M16 · tools/check-telepathy.py

Question: list every defect in this file that could make a check or instruction silently fail or be read two ways. Quoted with file and line.

## Defects

- `tools/check-telepathy.py` line 81: `check("alice cannot read bob's mail", call(env, "alice", "read", id=mid)[0] is None)`. This passes for any error from the server, including "message not found", a bad argument, or a server fault that returns `isError`. It never checks that the refusal is the permission refusal. The test can pass while the access control is broken, provided the read returns an error for some other reason.
- `tools/check-telepathy.py` line 82: `check("a bad mailbox name is refused", call(env, "alice", "send", to="../x", body="b")[0] is None)`. Same weakness. Any error passes, including the missing `subject` argument (the call on line 62 passes one; this call does not). The check does not show that the `../x` name is the reason for the refusal.
- `tools/check-telepathy.py` line 61 against lines 65 to 67: line 61 says "measured from before the send, so it includes the sender's start-up". The pass criterion is the wait on line 65, which starts after `call` returns (line 62), so it does not include the send. The docstring (line 6) says "within 2 s". Read two ways: the comment says the clock includes start-up, and the enforced window (line 65, 2 s) starts after the send. The printed `took` on line 67 and 86 is measured from line 61, so the reported figure and the enforced figure are different measures.
- `tools/check-telepathy.py` line 65: `woke, seen = wait_line(watcher, f"NEW {mid}", 2)`. `wait_line` (line 48) matches by substring (`if want in line:`). An id that is a prefix of another id, or a line such as `NEW {mid}-stale`, passes. The watcher's `NEW` line format is not pinned by this file.
- `tools/check-telepathy.py` line 59: `armed, seen = wait_line(watcher, "armed", 5)`. Substring match. Any watcher output line that contains the word "armed" passes the "watcher arms" check, including an error line such as "could not be armed". The check does not require the exact arming line.
- `tools/check-telepathy.py` lines 43 to 47 (inside `wait_line`, called from lines 59, 65): `select.select([proc.stdout], ...)` followed by `proc.stdout.readline()`. `proc.stdout` is a buffered text stream. When `readline()` reads a chunk that already contains the next line, the next `select` call sees an unready descriptor even though the line is in Python's buffer. The line is then missed, and the check at line 66 fails with "nothing printed". This is a false failure that appears only on timing, so it is intermittent. The `PYTHONUNBUFFERED=1` setting on line 55 applies to the child watcher, not to this parent-side buffer.
- `tools/check-telepathy.py` lines 45 to 47: when the watcher closes stdout, `readline()` returns `""` and `select` reports the descriptor ready at once. The loop spins until the deadline, with no exit on EOF. The result is a false "nothing printed" after the full timeout, not an immediate report that the watcher died.
- `tools/check-telepathy.py` line 34: `return json.loads(r.stdout)["result"]`, with `json.loads` on the whole of stdout. If the MCP server writes any extra line (a log line or a notification) before the response, the decode fails. The failure is loud but it is a crash, so the `FAILS` list collected so far is never printed (line 83 is not reached).
- `tools/check-telepathy.py` line 36: `return (None, text) if result.get("isError") else (json.loads(text), "")`. A successful call whose text is not JSON raises here, aborting `main()` and dropping every earlier FAIL. Same crash path as line 34.
- `tools/check-telepathy.py` line 80: `check("the message is kept as done", everything and everything["messages"][0]["status"] == "done", everything)`. If `messages` is empty the line raises `IndexError` instead of failing the check, so the run ends in a traceback with earlier FAILs lost. The same applies to `status` missing (`KeyError`).
- `tools/check-telepathy.py` lines 29 to 33 (`call`): the function passes `params` with no `initialize` handshake before the tools/call method, and it does not check `r.returncode`. A server that requires `initialize` returns an error object, which line 34 turns into a `KeyError`. The failure is loud, but the reason ("no initialize") is hidden behind a traceback.
- `tools/check-telepathy.py` line 33: `timeout=10` on `subprocess.run` raises `TimeoutExpired` on a slow server. That is loud, but it aborts the run before the `FAILS` list prints (same as line 34).
- `tools/check-telepathy.py` line 8: "The real mailbox (~/.local/state/telepathy) is never touched." The file sets `TELEPATHY_DIR` (line 55) and nothing else. Whether the server and watcher honor only `TELEPATHY_DIR` (and not, for example, an XDG state path) is not established in this file. If they do not, the test writes to the real mailbox and the docstring is false. This is a claim the file does not verify.
- `tools/check-telepathy.py` line 9: "Linux only (the watcher uses inotify)". The check does not test the platform. On another OS the watcher fails to arm (line 59), which reads as a telepathy failure, not as a platform skip.

## Notes

The end-to-end sequence on lines 56 to 81 (send, watch, inbox, read, mark_done) matches the docstring on lines 4 to 6. Each step is asserted by `check` (lines 24 to 26), which records failures in `FAILS` and prints them at the end (lines 83 to 84).

The watcher is always killed and waited on in the `finally` (lines 68 to 70), so a failed assertion does not leave a process running.

The temporary mailbox is removed by `TemporaryDirectory` (line 54) when the `with` block exits.

Lines 62 and 64 handle a failed send. `mid` becomes `"none"` (line 64), so the watcher check (line 65) fails loudly rather than matching an empty id.

The use of `call(...)[0]` (lines 81 and 82) and of `inbox and ...` (lines 72, 74, 76, 78) follows the convention that `None` means error. The convention is consistent, but it is the source of the weak error checks noted above.

The MCP server source (`tools/telepathy/telepathy_mcp.py`) and watcher (`tools/telepathy/watch.py`) were not read for this report. Every claim about their behavior (the `armed` and `NEW` line formats, the error text, and whether `initialize` is required) is unverified against them.
