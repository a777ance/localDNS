# M15 · tools/check-statements.py

Question: list every defect in this file that could make a check or instruction silently fail or be read two ways. Quoted with file and line.

## Defects

- `tools/check-statements.py` line 42: `GIGABYTES = re.compile(r"\bGB\b|gigabyte", re.IGNORECASE)`. The `\b` boundaries fail between a digit and `GB`, so an unspaced figure such as `9.5GB` is not seen. Checked in memory: `GIGABYTES.search("cost 9.5GB a day")` returns no match, while `"cost 9.5 GB a day"` matches. This is the volume detector for lines 207 and 219, so a volume printed as `9.5GB` in a config passes the no-volume gate. Units `MB`, `TB`, `GiB` and `bytes` are not detected at all.
- `tools/check-statements.py` line 56: `GB_FIGURE = re.compile(r"(\d+(?:\.\d+)?)\s*(?:GB|gigabytes?)\b", re.IGNORECASE)`. A thousands separator is not handled. Checked in memory: `"used 1,234 GB"` yields the figure `234`, not `1234`. The figure is then compared against the input numbers (line 74), so the wrong number can match and pass, or a real figure can be reported as a different number.
- `tools/check-statements.py` lines 20 and 21 against lines 67 to 69 and 231 to 233: the header says "every gigabyte figure printed in the page ... is a number the cfg itself carries", and the code checks against the input (`carried_input`, the stats and sidecar), not against the cfg. The docstring on lines 67 to 69 says the input. Read two ways: a reader of the header would think a figure in the cfg is allowed, and the code allows a figure from the input even when the cfg does not carry it.
- `tools/check-statements.py` line 231: `carried_input = json.dumps({"stats": stats, "sidecar": tempting_sidecar()}, ensure_ascii=False)`, with the sidecar value `"avg_daily_gb": 9.5` set on line 157. The cohort average is in the carried input, so a page that prints `9.5 GB` as this household's own volume passes the check at line 75 to 76. The cohort figure is exactly the invented-volume channel the gate exists to catch, and the gate lets it through.
- `tools/check-statements.py` line 74: `carried = {float(x) for x in re.findall(r"\d+(?:\.\d+)?", carried_input)}`. Any number that appears anywhere in the input (`"devices": 14` on line 144, `"count": 4` on line 154, `"peak": 31` on line 147) counts as "carried" for a GB figure. A figure of `14 GB` or `4 GB` is accepted because an unrelated field holds the same number. The match is by value, not by the field it came from.
- `tools/check-statements.py` line 78: `if not cfg.get("alloc") and ("Traffic Allocation" in body or "Total Volume" in body):`. This depends on two literal section titles. If the renderer renames a section, this check passes silently for that section. Line 237 would notice a rename only on the measured control, not on the no-volume cases.
- `tools/check-statements.py` lines 201 to 203: `for key in VOLUME_KEYS: if key in cfg:`. The key list is checked only against top-level keys of `cfg`. A volume value nested under another key (for example inside a `summary` row) or under a key not on the list passes this check. The text check on lines 206 to 210 is the only backstop, and it has the gaps in line 42.
- `tools/check-statements.py` line 98 to 100: `if name != "Other" and name not in by_category:`. Any row named "Other" is exempt from the "row was not in the input" check, even if its bytes did not come from the input. The total check on line 95 still holds, so only a reallocation that keeps the total is missed. The exemption is by name, not by value.
- `tools/check-statements.py` line 90 to 92: `pct_sum = sum(r[1] for r in rows)` with `if rows and pct_sum != 100`. If `build_alloc` returns float percentages, the sum may be `99.99999...` or `100.00000...01` and the check fails on rounding. That failure is loud, but it is a false failure that could push a maintainer to loosen the check.
- `tools/check-statements.py` line 136 and line 186: `KNOWN = []` with the comment "the three faults pinned here ... were fixed the same day (DEBT-013)". The loop on lines 186 to 192 is therefore empty, and the "pinned fault no longer reproduces" check cannot run. The comment says the list is a mechanism for known faults; the list is empty, so the mechanism is untested. Not silent, but the comment and the code can be read as "the pin is live".
- `tools/check-statements.py` lines 198 to 199: `except Exception as e:` converts a crash into a `problems` entry. The comment says "a crash is a finding, not a broken gate". A crash inside `compose` is reported as a FAIL for that case, and the loop `continue`s, so the no-volume checks for that case are skipped. The remaining checks for that case do not run, and the message does not say so.
- `tools/check-statements.py` line 211: `if len(cfg.get("summary", [])) != 6:` treats a missing summary as length 0. The message on line 212 says "the measured Account Summary is not six rows", which reads as a measured-data problem when the cause may be a renamed key.

## Notes

The header (lines 1 to 31) states the rule and lists four checks. Checks 1 to 3 (`build_alloc` and `compose`) are fully implemented on lines 83 to 105 and 177 to 221. Check 4 (the rendered HTML) is implemented on lines 223 to 238.

The import on line 225 catches only `ImportError`. Any other failure while loading `generate_client.py` (for example a `SyntaxError`) escapes as a traceback. That is loud, not silent.

Line 74 uses `float(x)` on every number. That makes `1` and `1.0` equal, which is what the check wants.

The random mixes (lines 125 to 131) use a fixed seed (line 125, `random.Random(777)`), so runs are repeatable.

The docstring (lines 23 to 26) says `compose.main()` and `render_all()` are not covered. That is an honest scope statement, not a defect.

Line 43's `VOLUME_KEYS` list is not checked against the keys `compose.py` actually emits in this file. The check's coverage therefore depends on that list staying current.
