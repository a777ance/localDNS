# M15 · tools/check-statements.py

## Defects

- tools/check-statements.py line 42: "GIGABYTES = re.compile(r"\bGB\b|gigabyte", re.IGNORECASE)". The "\bGB\b" alternative has no word boundary between a digit and "G", so a figure printed as "40GB" is not matched. Check 3 (line 207) and the control (line 219) both rely on this pattern, so a gigabyte figure written without a space passes silently.
- tools/check-statements.py line 56: "GB_FIGURE = re.compile(r"(\d+(?:\.\d+)?)\s*(?:GB|gigabytes?)\b", re.IGNORECASE)". The pattern only recognises "GB" and "gigabyte(s)". A figure printed as "GiB" or "TB" passes the render check at line 75 without being flagged.
- tools/check-statements.py line 74: "carried = {float(x) for x in re.findall(r"\d+(?:\.\d+)?", carried_input)}". The "carried" test takes every number in the JSON input as a permitted figure, including the date digits in "2000-01-01", the device count and the VPN count. A printed gigabyte figure that happens to equal any such stray number passes the honesty check at line 76 even though the input never carried it as volume.
- tools/check-statements.py line 231: "carried_input = json.dumps({"stats": stats, "sidecar": tempting_sidecar()}, ensure_ascii=False)". The sidecar includes the cohort "avg_daily_gb": 9.5 (line 157). That makes "9.5" an allowed figure, so a rendered page that prints a cohort "9.5 GB" with no measured volume passes the render check silently, against the rule the gate exists to enforce.
- tools/check-statements.py line 78: "if not cfg.get("alloc") and ("Traffic Allocation" in body or "Total Volume" in body):". The check depends on two hard-coded section titles in the rendered HTML. If generate_client.py renames either title, this test stops matching and the no-volume section check passes silently. Line 237 (the control) checks only "Traffic Allocation", so the two places read the section name two different ways.

## Notes

The gate imports compose.py and generate_client.py by path (lines 40 and 54) and does not catch a missing file. A missing file raises an uncaught FileNotFoundError, which is a loud failure, not a silent one.

The import at lines 223 to 227 catches only ImportError and tells the operator to install segno. Any other exception raised while loading generate_client.py propagates and stops the run, so it is also loud.

The KNOWN list at line 136 is empty. Its comment records that the three faults pinned there were fixed on 2026-11-12 (DEBT-013). The pinned-fault loop at lines 186 to 192 therefore does nothing on this run, and that is intended.

The docstring (lines 23 to 25) says that compose.main() and render_all() are not covered. The coverage claim in the header matches the code.

The random mixes at lines 126 to 131 use a fixed seed (777), so the synthetic inputs are the same on every run. The rounding-tie cases at lines 120 and 121 both total 1000, so their percentages (14.5% and 15.5%) are exact, which is what those cases are meant to test.
