# M07 · tools/check-decisions.py

## Defects

- tools/check-decisions.py line 15, ENTRY pattern "^- \*\*DEC-(\d{3}) · (.*)$": the gate only recognises entries that start with a bullet and bold DEC prefix. Any other layout, including the block-quote tile form "> **DECISION · DEC-NNN · ..." that CLAUDE.md prescribes for founder decisions, is skipped without a message, so its status and duplicate checks never run.
- tools/check-decisions.py line 15, ENTRY pattern "DEC-(\d{3}) · ": the id must be exactly three digits followed by one space and a middle dot. An entry such as "DEC-1000", "DEC-12" or "DEC-012 ·OPEN" is not matched and is silently dropped from every check.
- tools/check-decisions.py line 15, capture group "(.*)$" with re.MULTILINE: the body is only the first line of the entry. A status written on a continuation line (for example a line reading "Decision needed: GO or NO GO") is never seen by line 30, so a valid entry is reported as "has no status".
- tools/check-decisions.py lines 16 and 30, STATUS pattern "·\s*(OPEN|GO|NO GO|MOOT)\b" searched against "· " + body: the search matches any middle dot followed by a status word anywhere on the first line, including inside the question text. An entry whose question reads "· GO or NO GO?" passes with no real status, and "· GO-LIVE" also matches because \b accepts a hyphen.
- tools/check-decisions.py line 2, module docstring: "gate for the rule 'every founder decision is in the DEC log'". The script never checks that a founder decision exists in the log. It only validates the entries it can parse, so a decision that was never logged passes silently. The stated purpose overclaims what the check does.

## Notes

Line 20 calls read_text with no error handling. A missing or unreadable docs/ai-cto/blocked.md produces a traceback and exit code 1, which is loud, not a silent pass. This is not counted as a defect.

Line 33 treats "newest first" as descending numeric id. That matches sequential DEC numbering and is consistent with the docstring on lines 4 to 7, so it is not a defect.

Line 15 uses "$" in MULTILINE mode, which matches before a newline only. If blocked.md has CRLF line endings, the captured body keeps a trailing carriage return. The STATUS search still succeeds, so this does not change any result.

Exit codes are correct: line 39 returns 1 when any problem is recorded and 0 otherwise, and line 43 passes that to sys.exit.
