## Defects

- `tools/check-decisions.py:15` is `ENTRY = re.compile(r"^- \*\*DEC-(\d{3}) · (.*)$", re.MULTILINE)`. It matches only single-line bullets that start with `- **DEC-`. A DEC entry written in another shape is not counted and raises no failure. The founder-decision tile in `CLAUDE.md` is a blockquote beginning `> **DECISION · DEC-NNN`, which this pattern does not match. The gate fails only when the count is zero (`:23-24`), so a log written in the tile shape passes silently.
- `tools/check-decisions.py:15` also requires the literal middle dot U+00B7 and exactly three digits. An entry that uses a hyphen, a bullet or any other separator is skipped in the same silent way.
- `tools/check-decisions.py:15` captures only the first line of an entry, through `(.*)$`. A status written on a following line, such as "Decision needed: **GO**", is never seen by the check. The entry then fails with "has no status," or, if its first line happens to contain a status word, passes for the wrong reason.
- `tools/check-decisions.py:30` runs `STATUS.search("· " + body)`, which searches the whole captured line and not the status position. Any "· GO", "· OPEN" or similar phrase in the question text satisfies the check, so an entry with no status can pass.
- `tools/check-decisions.py:16` is `STATUS = re.compile(r"·\s*(OPEN|GO|NO GO|MOOT)\b")`. The `\b` boundary accepts a hyphen as the end of a word, so "· GO-LIVE" in a title counts as the status GO.
- `tools/check-decisions.py:2` says the gate enforces "every founder decision is in the DEC log." The code checks the format of the entries it can parse. It does not check completeness, so a reader can take the docstring as a guarantee that the code does not give.
