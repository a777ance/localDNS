## Defects
- Lines 54 and 56: the reply text is the last assistant record with any text. If the final turn ends in a tool call with no text, LEAD and LANDING check earlier prose; multi-block replies are checked only on their last block.
- Lines 70-76: only numbered Decide items are read, and the list ends at the first blank or non-numbered line. A list with a blank line between items, or a wrapped line, is truncated, so ACT requires fewer lines. A Decide list written as `-` bullets is never recognised, and ACT is skipped (line 179).
- Lines 88 and 90: the Act section ends only at `#` headings or a single bold word, so list lines in the L section count as Act lines. Line 90 counts any list line, including sub-bullets, so one item with three sub-bullets satisfies a three-item Decide list.
- Line 110: `named = [f for f in new if f in text]` is a substring test; naming `.../scratchpad/xy` marks `.../scratchpad/x` as announced.
- Line 106: with an empty session id and no scratch directory variable, the SCRATCH check is silently disabled.
- Lines 187 and 205: the regex matches only an exact bash opener. `sh` blocks, a trailing space, and CRLF blocks skip CD and REHEARSE without a message.
- Line 198: `"Not rehearsed:" not in text` exempts the whole reply once the phrase appears anywhere; the docstring says the exemption is per command.
- Line 251: `"Stopping because:" not in text` exempts NEXT when the phrase appears anywhere; the docstring and the L-section break require a line that starts with it.
- Lines 136-139: the queue regex matches only the SQ and Q formats; other formats match nothing, and line 139 returns None, reporting nothing waiting.
- Line 137: `re.search(r"BLOCKED|DONE|SKIPPED", ...)` is case-sensitive, so `NOT DONE` or `UNDONE` skips that item.
- Lines 122-124: `except Exception: dirty = []` makes a git failure look like a clean tree, so NEXT returns nothing.
- Lines 229 and 232: if the blocked log is missing, the DEC-entry check is skipped silently.
- Line 231: `if part not in text` checks the whole reply, not each tile; one complete tile hides a missing part in another.
- Line 34: the hedge list is closed; "likely works", "should pass" and "probably fine" are not caught.
- Line 153: any list item containing a DEC id is exempt from L ITEMS OPEN; L items written as plain paragraphs are never counted.
- Lines 281-282: any exception inside `review()` returns 0, which allows the stop. A bug in any check fails open with no message.

## Notes
The L STEP check (line 238) flags any "### Limits" or "### Open items" heading in an ordinary reply; that is a loud false positive. The fail-open on malformed JSON (line 275) and the once-per-turn guard (line 276) match their comments.
